# OpenDPD Studio frontend

React 19 + TypeScript (strict) + Vite + MUI + Plotly (basic bundle).
Served by the FastAPI app from `opendpd/studio/static` after `npm run build`;
end users never need Node.js (S06 packages the build into the wheel).

```bash
cd frontend
npm ci
npm run dev            # http://127.0.0.1:5173, proxies /api to a running `opendpd gui` on 8765
npm run typecheck      # tsc -b, strict, no `any`
npm run lint           # oxlint
npm test               # Vitest + Testing Library (jsdom)
npm run build          # -> ../opendpd/studio/static
npm run e2e            # Playwright journeys on the preview build with a mocked API (also visual baselines)
npm run types:generate # regenerate src/api/schema.ts from ../docs/contracts/openapi.json
```

## Where things are

| Path | Purpose |
|---|---|
| `src/api/schema.ts` | generated from the OpenAPI contract; never edited by hand (`npm run types:check` in CI) |
| `src/api/client.ts` | fetch wrapper: same-origin cookies, CSRF header on writes, `ApiError` from the error envelope |
| `src/api/hooks.ts` | TanStack Query hooks: the only place server state is cached |
| `src/api/events.ts` | SSE subscription and the event reducer (progress, metrics, status, heartbeats) |
| `src/i18n/en.json` | every user-facing string |
| `src/theme/tokens.json` | design tokens (colours, spacing, typography); MUI theme and Plotly layouts derive from it |
| `src/components/` | domain components from the UX spec: MetricCard, EvidenceBadge, SpectrumPlot, IQPreview, DiagnosticItem, RunTimeline, ConfigDiff, LogViewer, StatusChip, state blocks, PlotlyChart |
| `src/pages/` | Home, Datasets, Experiments (+ new form), Run detail, Results, Settings, component gallery (mock) |
| `mocks/` | fixtures generated by `python -m opendpd.schemas export-mocks --out frontend/mocks` (a Python test keeps them in sync) |
| `e2e/` | Playwright journeys against `e2e/mock-api.ts` |

## State model (S05)

- **Server state** lives in TanStack Query keyed by resource; the run detail
  page subscribes to `/runs/{id}/events` and only *invalidates* the run
  snapshot on status changes. The frontend never decides a run's status.
- **URL state**: route params (`/runs/:runId`), `?tab=`, `?status=` filters.
- **Local state**: form edits, dialogs, log filter. Form defaults are
  derived during render from the recipe/dataset lists, never copied.

## Visual baselines

`e2e/journey.spec.ts-snapshots/` holds Chromium/Linux screenshots of the
component gallery captured locally (`npx playwright test --update-snapshots`).
CI runs the same journeys with `--ignore-snapshots` because font rendering
differs between machines; compare visually before merging UI changes.
