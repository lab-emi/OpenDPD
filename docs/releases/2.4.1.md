# OpenDPD Studio 2.4.1

OpenDPD 2.4.1 adds the **NR FR1 standard test models of 3GPP TS 38.141-1** to the Signal Generator. The **5G NR** tab now opens on a test-model picker instead of the preset matrix, and the models take every parameter the standard leaves open: duplex mode, up to 16 carriers, subcarrier spacing and channel bandwidth per carrier, cell identity, gaps between carriers, rank for the time-alignment model and the NB-IoT settings of NR-N-TM. It is a patch release: nothing else in Studio, the CLI, the Python SDK or the MATLAB toolbox changes behaviour.

```bash
uv pip install --python .venv --upgrade "opendpd==2.4.1" --torch-backend=auto
uv run --no-project --python .venv opendpd gui
```

The wheel includes Studio. The output is a baseband stimulus that follows the standard's definition of each model. It is **not** a conformance waveform, was not compared with an instrument, and its EVM is an ideal-demodulation diagnostic (see [Not verified](#not-verified)). The guide [NR standard test models](../guides/nr-test-models.md) documents every parameter, convention and limit.

## What is new

* **Eleven models** of TS 38.141-1 V18.14.0 clause 4.9.2.2: NR-FR1-TM1.1, 1.2, 2, 2a, 2b, 3.1, 3.1a, 3.1b, 3.2, 3.3 and NR-N-TM (NB-IoT operation in NR in-band), each with its clause, description, the tests it is defined for, and a read-only **Defined by the standard** table that resolves for your settings: N_RB, FFT size, resource-block-group size and indices, every user with modulation, PRB ranges and level, and the TDD pattern.
* **Single and multi-carrier.** Carriers are placed at the nominal channel spacing of TS 38.104 clause 5.4.1.2 (100 kHz-raster bands), centred at baseband DC, with equal power spectral density and cell identities 1, 2, … in ascending frequency unless overridden. An optional gap before a carrier (a multiple of 0.3 MHz) models a non-contiguous sub-block. Mixed subcarrier spacings are allowed with a warning.
* **FDD and TDD.** TDD follows table 4.9.2.2-1 (15 kHz D D D S U, 30 kHz D×7 S U U, 60 kHz D×14 S S U×4); flexible and uplink symbols are exactly zero samples. Standard duration: 10 ms FDD, 20 ms TDD.
* **Two readings of the PN23 rules.** *Standard text* (one stream per user, restarted every frame) or *MATLAB 5G Toolbox* (one stream per PDSCH allocation, never restarted), plus the standard's PN23 scope choice for TDD. In a single 10 ms FDD frame of TM1.1, 1.2 and 3.x the two give identical grids.
* **Two layers for TM1.1** (ports 1000 and 1001, no precoding, as defined for the TAE test); the generator exports one of the two ports.
* **NR-N-TM**: the NR-FR1-TM1.1 signal with one NR resource block replaced by the NB-IoT test model of TS 36.141 (NPSS, NSSS, NRS, NPBCH, NPDCCH, NPDSCH), FDD at 15 kHz, 3–50 MHz, lower, upper or both edge positions, boost X from 3 to 12 dB.
* **Capture control.** Oversampling (automatic, 1, 2, 4 or 8) and capture length in subframes. Studio captures hold at most 1,000,000 samples, so wide or multi-carrier signals can be **shortened** to whole subframes; the panel, the analysis and the notes say so.
* **Preview.** The coverage label reads *3GPP test model*; the allocation plot shows every carrier in MHz; per-carrier N_RB, cell ID, centre offset and EVM are in the analysis; the notes state the conventions, truncation and the definition of the shown EVM.
* **The matrix is behind a button.** **Generic numerology matrix…** reveals the 1,186-preset catalog's NR matrix, labelled as generic engineering stimuli that are not standard test models. Selecting matrix cells works as before and joins the same selection of up to 16 signals. Wi-Fi 6, Wi-Fi 7 and Custom are unchanged.
* **Dataset names** carry the model: `syn_pa_in_nrtm3p1a_bw98p31M_q256_c1_n1`, `nrntm` for NR-N-TM.
* **API.** `GET /signal-generator/nr-test-models` returns the catalogue and `POST /signal-generator/nr-test-models/resolve` returns the complete validated generator configuration and a summary for a recipe. `GeneratorConfig` has an optional `nr_test_model` recipe, `GeneratorAnalysis` an optional summary, and `GeneratedSignal.coverage` the new value `standard_test_model`.

## Parameter ranges

| Parameter | Range |
| --- | --- |
| Models | NR-FR1-TM1.1, 1.2, 2, 2a, 2b, 3.1, 3.1a, 3.1b, 3.2, 3.3, NR-N-TM |
| Duplex | FDD, TDD (NR-N-TM: FDD) |
| Carriers | 1–16 |
| Subcarrier spacing | 15, 30, 60 kHz (NR-N-TM: 15 kHz) |
| Channel bandwidth | 15 kHz: 3–50 MHz · 30 kHz: 5–100 MHz · 60 kHz: 10–100 MHz, the 40 cells of TS 38.104 table 5.3.2-1 (NR-N-TM: 3–50 MHz) |
| Cell identity | automatic (1, 2, …) or 0–1007 per carrier |
| Gap before carrier 2…n | 0 or a multiple of 0.3 MHz, up to 1000 MHz |
| Layers / exported port | 1 or 2 (TM1.1 only) / 1000 or 1001 |
| PN23 convention / TDD scope | standard text or MATLAB / downlink symbols or all symbols |
| NB-IoT | lower, upper or both edge positions; boost X 3–12 dB (default 6) |
| Oversampling | automatic, 1, 2, 4, 8 |
| Capture length | standard (10 or 20 subframes) or 1–20 subframes, at most 1,000,000 samples |

Also available as before for every signal: RMS, seed, RF carrier metadata, burst envelope, phase offset and jitter, frequency offset, I/Q gain and phase mismatch, DC offsets, SNR, clipping and the optional ideal filter (off for test models).

## Evidence

* **Resource grids against MATLAB R2026a (5G Toolbox 26.1).** MATLAB generated the ten FR1 models for FDD and TDD at 15, 30 and 60 kHz, several bandwidths (TM1.2 and TM3.3 at all 39 cells its wrapper accepts), cell IDs 1–1007 and 1–40 subframes: **438 configurations were compared with the package's grids (`data_convention="matlab"`); 414 are bit-identical and the other 24 agree within 3.2×10⁻¹⁶** (one unit in the last place of the boosted amplitudes `10^(P/20)` of TM1.2 and TM3.3). Fed with MATLAB's grids, the package's OFDM modulator reproduces the 58 saved MATLAB waveforms to 4.4×10⁻¹⁷. The repository carries SHA-256 digests of the 438 grids and a test (`tests/unit/test_nr_tm_grid_parity.py`) that checks them; it carries no MathWorks code or data.
* **Two layers.** One two-layer TM1.1 grid (10 MHz, 15 kHz) obtained by setting two layers by hand on MATLAB's TM1.1 configuration is reproduced bit for bit on both ports; this case is not stored in the repository.
* **Specification double entry.** The resource-block-group selection, boost levels and power conservation of TM1.2, TM3.2 and TM3.3 for all 40 table cells were transcribed independently from page images of TS 38.141-1 and agree with the implementation and with closed forms written separately in the tests. N_RB equals TS 38.104 table 5.3.2-1. PN23, Gold, the five QAM constellations and the DM-RS sequences are checked against literal implementations of the defining equations. At nominal spacing no ordered pair of table cells has overlapping occupied subcarriers (tightest gap 7.5 kHz, asserted by a test).
* **NB-IoT building blocks against MATLAB LTE Toolbox.** NPSS, NSSS, NRS, NPBCH, NPDCCH and NPDSCH symbols, resource-element sets and mapping order agree with MATLAB R2026a's NB-IoT functions to 10⁻¹² (NSSS 2×10⁻¹¹) for 13 combinations of cell identity, host cell ID and operation mode, and the NSSS sequence for 16 (N_ID, frame) pairs covering all four sequence tables. The puncturing, power split and placement into the NR grid have no reference to compare with.
* **Time domain and limits.** Tests cover cyclic-prefix lengths, exact sample count, RMS, exact zeros in TDD uplink, demodulation of the output back to the grid, oversampling, carrier placement and equal power spectral density, and the refusal of invalid setups (for example 5 MHz at 60 kHz, rank 2 on TM3.1, overlapping carriers, more than 1,000,000 samples). Without impairments the shown EVM is about 10⁻⁶ %, the single-precision floor of the exported samples.
* **Cost.** Four 100 MHz carriers at 30 kHz (983,040 samples at 491.52 MS/s) synthesised in about 0.3 s with a peak below 0.4 GB on the development machine.

## Upgrade notes

* **Signal identities.** Signals that are not test models keep their identifiers: their serialised configuration is byte-identical to 2.4.0 (the new `nr_test_model` key is omitted when unset) and the hashed generator sources are unchanged. Saved signals, datasets, manifests and configuration files from 2.4.0 load unchanged, and a 2.4.0 configuration without the new key keeps working in the new panel. The identity of a test-model signal also covers the sources of the test-model package.
* **Restart a running service.** A Studio service that is still running 2.4.0 in a workspace must be stopped and started again after the upgrade: the Python SDK refuses to attach to a service of another version. Reload open browser tabs to get the new interface.
* **Hosted Studio.** The two new routes are on the public allowlist of this release; the hosted API must be redeployed to serve them. Until then the redeployed web build shows the NR matrix, as the test-model catalogue request is refused. The resolve route is a pure function of the recipe: it writes nothing to the workspace, takes no mutation or storage reservation, is rate-limited per network and answers an invalid body with 422 before computing anything.
* **MATLAB toolbox.** The toolbox stays at **2.4.0** and is compatible: it uses capability strings, not the Python version, and reads none of the new fields. MATLINK opens the same Signal Generator, so its NR default is now the standard test model. `Matlab/toolbox/docs/gui.md` was reworded; no new `.mltbx` is released.
* **API contract.** `docs/contracts/openapi.json` and the generated frontend types contain the additive changes. No new dependency.

## Not verified

* **Any instrument or hardware.** No signal was compared with the output of a commercial signal generator or with a base station, and no conformance measurement was made; the PN23 polarity of other instruments is unknown.
* **Python 3.10, 3.11 and 3.12** were not run locally (development machine: Python 3.13); the compute suite covers 3.10–3.13 in CI.
* **Independent references are missing** for multi-carrier composition (checked against the spacing formula and by demodulating each carrier), the standard-text PN reading beyond one frame, the 3 MHz cells (MATLAB's test-model wrapper rejects them), TDD data bits beyond MATLAB's own convention, and the NR-N-TM puncturing, power split and placement. No MATLAB release other than R2026a was used; TS 38.141-1 versions other than V18.14.0 were not compared, and the NB-IoT clauses were read in TS 36.141 V19.1.0 although the NR specification cites it without a version.
* **EVM and level.** The shown EVM is an ideal-demodulation diagnostic, not clause 6.5.3 receiver EVM; levels are RMS-normalised, not calibrated power. SSB, CSI-RS, PT-RS, PRACH, channel coding, the NRTC test-configuration rules, NRTC6 ON-OFF patterns, nominal spacing for 15 kHz-raster bands, FR2 models (TS 38.141-2) and TDD for NR-N-TM are not implemented.
* **Browser, CI, review and release status** are recorded in the release checks below.

## Differences from the plan

* Two readings of the standard's PN23 rules are offered because the text ("can be generated per user", restart "in the first allocated slot of each frame") and MATLAB's behaviour (one stream per allocation object, no restart) differ; the default follows the text.
* The nominal channel spacing uses TS 38.104 clause 5.4.1.2 for 100 kHz-raster bands. TS 38.141-1 refers to clause 5.4.1 without saying which sub-clause applies; both give non-overlapping carriers and differ by up to 0.3 MHz per pair.
* NR-N-TM is generated for FDD at 15 kHz only. No standard defines NB-IoT in-band operation for 30 or 60 kHz hosts, and TDD would need special-subframe budgets that none gives.

## Deployment

Deploy the same revision to the API, private GPU agent and pinned worker image, then update `STUDIO_REF` in `lab-emi/opendpd-site` and deploy its Pages workflow. Follow [Public Studio](../architecture/public-studio.md#deployment).
